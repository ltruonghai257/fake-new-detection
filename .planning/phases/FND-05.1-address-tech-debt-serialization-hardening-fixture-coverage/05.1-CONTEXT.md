<domain>
## Phase Boundary

Add runtime toggles for PhoBERT and COOLANT so callers can choose which trained-model signals participate in a fact-check. Keep all A2A agents operational regardless of toggle state. Change the default debate configuration to ground the real/fake advocates and judge in COOLANT results and web evidence (PhoBERT disabled by default). Add prompt-overload hooks so any agent system prompt can be replaced from `Settings` / env vars in the future without editing agent code.

**In scope:**
- `Settings` / `initial_state()` defaults for `use_phobert`, `use_coolant`, `use_evidence`
- `evaluate_agent.py` honoring `use_phobert` and `use_coolant`
- `debate_utils.py`, `real_advocate.py`, `fake_advocate.py`, `judge_agent.py` prompts adapted to available models
- `agreement_gate.py` and `conclusion_agent.py` continuing to work when PhoBERT is unavailable/disabled
- A2A transport and `test_agent_http.py` unchanged and passing
- `Settings` extension for `real_advocate_prompt`, `fake_advocate_prompt`, and new `judge_prompt` / `conclusion_prompt` overrides
- Tests covering toggled runs and custom-prompt loading

**Not in scope:**
- Changing the A2A protocol, ports, or `a2a_client.py` / `a2a_server.py` architecture
- Training pipeline or model retraining
- React frontend changes
- New LLM models or agent roles
- Full prompt-file directory implementation (only the hook/extension point)

<decisions>
## Implementation Decisions

### Model ablation toggles

- **D-01:** `use_phobert`, `use_coolant`, and `use_evidence` are already in `FactCheckState` (ablation toggles). Add `Settings` fields and env vars `FACTCHECK_USE_PHOBERT`, `FACTCHECK_USE_COOLANT`, `FACTCHECK_USE_EVIDENCE` so `initial_state()` can default them centrally. **Default values:** `use_phobert=False`, `use_coolant=True`, `use_evidence=True` — this gives the COOLANT + evidence default the user asked for. — **Reversibility:** reversible — defaults can be flipped in `config.py`.

- **D-02:** `evaluate_agent.py` must read `state["use_phobert"]` / `state["use_coolant"]` and skip the corresponding model call. When skipped, emit a `ModelResult` with `available=False` and a `note` explaining the toggle (mirrors the pattern already in `verify_agent.py`). The A2A `EvaluateAgentHandler` continues to wrap `evaluate_agent` unchanged, so the HTTP service still runs. — **Reversibility:** reversible — behavior controlled by state flags.

- **D-03:** `verify_agent.py` already respects `use_phobert` / `use_coolant`; only `evaluate_agent.py` and `initial_state()` need changes to make the toggles usable end-to-end. — **Reversibility:** n/a (no change).

### Debate default: COOLANT + evidence

- **D-04:** `debate_utils.py` `_build_advocate_user_message()` and `_format_model_results_verdict()` must build the user message from the subset of `model_results` that are `available`. If `use_phobert=False`, the message must not mention PhoBERT; if `use_coolant=False`, the message must not mention COOLANT. The message header changes from the hard-coded "PhoBERT + COOLANT" to a dynamic list. — **Reversibility:** reversible — string formatting change only.

- **D-05:** `judge_agent.py` prompt currently hard-codes "PhoBERT và COOLANT". For this phase, replace the prompt string with a version that is neutral about which models are present, or keep the existing prompt but rely on the `model_detail` formatting to only show available models. The cleanest approach is to refactor the prompt to say "các kết quả model" and let `_format_models()` inject the concrete available ones. — **Reversibility:** reversible — prompt edit.

### A2A must keep running

- **D-06:** No structural change to `a2a_server.py`, `a2a_client.py`, or `scripts/start_agents.sh`. The only A2A-relevant code is `evaluate_agent.py` and the `EvaluateAgentHandler` wrapper, which already calls `evaluate_agent(state)`. Existing `test_agent_http.py` for `evaluate_agent` must continue to pass; add one test that passes `use_phobert=False` and confirms `TaskResult.output["model_results"]` contains a disabled PhoBERT entry. — **Reversibility:** reversible — no protocol change.

### Prompt customization hooks

- **D-07:** The user wants to customize agent prompts in the future. Add `Settings` fields `judge_prompt` and `conclusion_prompt` (env vars `FACTCHECK_JUDGE_PROMPT` / `FACTCHECK_CONCLUSION_PROMPT`) and use them in `judge_agent.py` / `conclusion_agent.py` if non-empty. Keep `real_advocate_prompt` and `fake_advocate_prompt` as-is. This pattern lets future phases add `search_prompt`, `expert_prompt`, etc. by following the same `Settings` field + env var + `prompt or DEFAULT` one-liner. — **Reversibility:** reversible — fallback to existing default prompts.

- **D-08:** `factcheck_agents/prompts.py` remains the canonical prompt module. Add a comment / docstring documenting the override convention and the list of env vars. Do not introduce a new prompts directory until a future phase asks for file-based overrides. — **Reversibility:** n/a (docs)./n
</decisions>

<specifics>
## Specific Ideas

- `Settings` fields (suggested):
  ```python
  use_phobert: bool = field(default_factory=lambda: os.getenv("FACTCHECK_USE_PHOBERT", "").lower() in ("1", "true", "yes"))
  use_coolant: bool = field(default_factory=lambda: os.getenv("FACTCHECK_USE_COOLANT", "1").lower() not in ("0", "false", "no", ""))
  use_evidence: bool = field(default_factory=lambda: os.getenv("FACTCHECK_USE_EVIDENCE", "1").lower() not in ("0", "false", "no", ""))
  judge_prompt: str = field(default_factory=lambda: os.getenv("FACTCHECK_JUDGE_PROMPT", ""))
  conclusion_prompt: str = field(default_factory=lambda: os.getenv("FACTCHECK_CONCLUSION_PROMPT", ""))
  ```
  Make `initial_state()` use `settings.use_phobert` etc. as defaults.

- `evaluate_agent.py` with ablation:
  ```python
  results = []
  if state.get("use_phobert", True):
      results.append(_phobert().predict(statement, evidence_text, evidence_count))
  else:
      results.append(ModelResult(model="phobert_vifactcheck", available=False, note="disabled by ablation toggle"))
  if state.get("use_coolant", True):
      results.append(_coolant().predict(statement, image_path))
  else:
      results.append(ModelResult(model="coolant", available=False, note="disabled by ablation toggle"))
  ```

- `debate_utils.py` dynamic header: if `use_phobert=False`, the message header becomes "KẾT QUẢ PHÂN TÍCH CỦA COOLANT VÀ BẰNG CHỨNG" or generic "KẾT QUẢ PHÂN TÍCH CỦA CÁC MODEL".

- New test: `test_evaluate_toggles` in `tests/factcheck_agents/test_evaluate_agent.py` — call `evaluate_agent(FactCheckState(..., use_phobert=False, use_coolant=True))` and assert the result list has `coolant` available and `phobert` unavailable with the right note.

- `test_agent_http.py`: add `test_evaluate_agent_disabled_phobert` sending a `Task` with `input["use_phobert"]=False`; assert the HTTP result still has `TaskResult.status="completed"` and the correct `model_results` shape.

</specifics>
